# Record an Incident

Document incidents and near-misses to improve risk management.

- **Niveau :** Intermediate
- **Durée de lecture :** 30 min
- **Tags :** Incident, Documentation, Analysis


## What is an Incident?

An **incident** is an event that occurred and has an impact on the organization.

## Steps to Record an Incident

**Location** : Risk Management → Incidents & Losses → Record

**Step 1: Basic Information**
1. Click **"Record an incident"**
2. Fill in the fields:
   - **Incident title** : Ex: "Main server outage"
   - **Description** : Detailed description of the incident
   - **Occurrence date** : When the incident occurred
   - **Incident type** :
     - Real incident
     - Near-miss (near-accident)
   - **Associated risk** : If the incident is related to an identified risk

**Step 2: Impact**
1. **Financial impact** (if applicable):
   - Estimated amount
   - Currency
2. **Operational impact** :
   - Impact description
   - Interruption duration
3. **Reputation impact** :
   - Assessment (Low, Medium, High)

**Step 3: Analysis**
1. **Root cause** :
   - Use the 5 Whys or Ishikawa method
   - Document identified causes
2. **Corrective actions** :
   - Immediate actions taken
   - Preventive actions to implement

**Step 4: Save**
1. Verify all information
2. Click **"Record the incident"**

## Analyze an Incident

After recording, you can:
- Perform root cause analysis (RCA)
- Create corrective actions
- Link to existing risks
- Generate incident reports
